* Private pipe ACL and overlapped cancellation
test-os1-private.py --mode pipe runs the actual private adapter with the exact
runtime and no registry writes. It observes the default DACL, applies a
temporary read/write deny ACE to that owned endpoint, requires a new connection
to fail with ERROR_ACCESS_DENIED=5, restores the original DACL in finally and
requires a new connection to return the exact ENGINE ddskk reply.

The same probe issues an actual pending client overlapped ReadFile, observes
ERROR_IO_PENDING=997, calls CancelIoEx on that exact OVERLAPPED, waits for its
event and drains ERROR_OPERATION_ABORTED=995. It then requires the next
request/reply to remain byte-exact on the same handle. Measured cancellation:
0.015700 ms. Positive controls before/after prevent unrelated connection
failures or a stolen next response from counting as security/cancel success.

Observed default DACL grants full access to SYSTEM, administrators and the
creating account, plus file-read to Everyone and Anonymous. This is an
observation, not a least-privilege approval. The probe qualifies ACL enforcement
and client overlapped cancellation on the retained boundary; it does not
qualify low-IL/AppContainer compatibility or a replacement overlapped server.
All changes to the tested ACL are confined to the owned private pipe.

* DNS: real worker observation remains INCOMPLETE
The test-only NATIVEIME_TEST_OS1_DNS_TRACE hook is under windows/host and is
active only with diagnostics=1, a private NativeIME-test registry name and an
EH private pipe name. It traces real getaddrinfo entry/exit and worker Stop
request/join; it adds no sleep, fake resolver, timeout, bypass or new normal
resolver behavior. Start-command spawning is disabled in the probe.

The probe queues LOCAL SERVER for an uncached reading with a unique hostname
under the reserved .invalid domain, waits for resolver entry, submits SHUTDOWN,
records its acknowledgement and applies the unchanged five-second private-soak
shutdown ceiling. A resolver entry without an exit at the pre-shutdown
observation is recorded as pending_at_shutdown; this is an observable trace
interval, not proof of a kernel operation at a microsecond boundary.

Measured run: SERVER PENDING; pending_at_shutdown=true; shutdown acknowledgement
0.084200 ms; host exit 251.693900 ms; real resolution exit status 11001
(normal name-not-found), resolver trace interval 36.700600 ms. Worker Stop
joined after the resolver exited. There was no cancelled resolver result.
The probe exits nonzero with INCOMPLETE DNS cancellation even though this
particular lookup ended quickly. Fast completion must not substitute for
cancellation qualification.

ServerCache::Stop sets stop_ and joins. ConnectDictionaryServer uses synchronous
getaddrinfo with no owned cancellation token. A diagnostics-only trace cannot
make that normal production call cancellable. Completing DNS cancellation
requires separately scoped native resolver work (for example an asynchronous
GetAddrInfoExW operation with an owned cancellation handle, bounded completion
drain, result cleanup and stale-generation fencing). That production change is
not hidden in this test hook. No deterministic fake delay is accepted as real
DNS cancellation evidence. S6 OS1 remains unqualified for DNS and low-IL/server
replacement; the new -Stage Os1 collects the feasible probes without running
the known-red policy resource gate first.
