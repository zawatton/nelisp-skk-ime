* A: cancellable native resolution
ConnectDictionaryServer now uses GetAddrInfoExW, a manual-reset OVERLAPPED
event and GetAddrInfoExCancel. Resolution has a 150 ms phase deadline, matching
the existing external socket-I/O ceiling; the existing 200 ms provider cache
wait, TCP connect ceiling per address and 150 ms exchange deadline are
unchanged. Previously DNS itself had no deadline. Shutdown is checked against
both g_stopping and the ServerCache worker's atomic stop flag, at intervals
of at most 5 ms while waiting. No resolver runs in the input callback.

Returned address lists are traversed in resolver order with the same AF_UNSPEC,
SOCK_STREAM and IPPROTO_TCP hints. Nothing sorts or filters the result list.
Resolver errors and cancellation still map to INVALID_SOCKET and the existing
negative server reply; obsolete config generations still discard replies.
The worker does not spawn a dictionary server after shutdown cancellation.
The Unicode API receives the original wide hostname directly.

Cancellation must be followed by completion drain before event/result/storage
release or WSACleanup. The drain waits for the completion event; it is not
abandoned after an arbitrary timeout. Microsoft's documented cancellation
contract signals completion immediately, but legacy namespace providers may
continue internal synchronous work. The probe measures the actual cancellation
and drain on this Windows installation; it does not claim that every installed
third-party provider stops its internal work.
References: [[https://learn.microsoft.com/en-us/windows/win32/api/ws2tcpip/nf-ws2tcpip-getaddrinfoexw][GetAddrInfoExW]],
[[https://learn.microsoft.com/en-us/windows/win32/api/ws2tcpip/nf-ws2tcpip-getaddrinfoexcancel][GetAddrInfoExCancel]].

The private hook requires all existing OS1 trace gates: diagnostics=1,
NATIVEIME_TEST_OS1_DNS_TRACE=1, a NativeIME-test registry branch and an EH private
pipe. Only with these gates and NATIVEIME_TEST_OS1_DNS_SERVER=127.0.0.2 does it
use ADDRINFOEX6 with an exclusive per-query UDP DNS server and cache bypass.
This API requires Windows build 22000 or newer. Production uses ordinary
namespace resolution without a custom server. No DNS adapter settings,
HKCU keys, hosts file or live IME configuration are changed.
Reference: [[https://learn.microsoft.com/en-us/windows/win32/api/ws2def/ns-ws2def-addrinfoex6][ADDRINFOEX6 custom DNS servers]].

test-os1-private.py --mode dns exclusively binds 127.0.0.2 UDP/53. It fails
if that endpoint is occupied; it never reconfigures or stops another server.
An ordinary NXDOMAIN, immediate failure or missing DNS packets fails the gate.
The fixture first withholds real UDP replies, then answers A with loopback
and AAAA with NODATA, then withholds replies again. On one host, serially:

1. A real pending resolution reaches the 150 ms deadline. Successful cancel
   status=0, completion WSA_E_CANCELLED=10111, real received DNS packets and
   drain <=1000 ms are mandatory; total first resolution must be <=1000 ms.
2. A new reading goes through the same worker and obtains the exact
   SERVER 1/S6-DNS/ reply from the fixture's TCP server. TTL=0 and per-query
   cache bypass prevent the shutdown case from using a cached address.
3. A new pending resolution receives SHUTDOWN. Successful shutdown cancel,
   status=10111, drain <=1000 ms and the existing 5 s process shutdown ceiling
   are mandatory. Host job and fixture sockets/threads are closed in finally.

These new resolver assertions supplement rather than weaken existing gates.
The code is compiled; this real cancellation probe has NOT been executed.

* B: policy allocation changes
The stream loop reuses a 4096-byte frame buffer, the numeric field vector,
a bounded decimal-string cache and a 4160-byte reply buffer. It scans each
read chunk by index, handles all complete frames in order, and retains a
partial frame by its used length. There is no pending-buffer concat, line
substring, tail substring, frame cons or per-request numeric vector.
EOF still discards an incomplete frame; newline, byte/field/context/kind
validation and raw decimal reply spelling remain unchanged.

Decimal strings must have exactly the original field length. Inspection of
the read-only runtime sources found that padding a reusable decimal string
would leave the integer fast path and could change overflow behavior.
The final implementation therefore caches one mutable exact-length string
per observed digit length, copying characters by index before calling the
same string-to-number. Each new length allocates once, subsequently reused
across fields and requests. The cache has 4097 slots; even adversarially
observing every length gives a bounded sum of 8,390,656 ASCII characters
(actual object/storage overhead is runtime-dependent). No arithmetic parser,
integer cap or input special case is substituted. Finite framing probes
compare six decimal strings, including overflow-size tokens, with the exact
runtime's direct string-to-number result.

The reply buffer copies the original qid/host/epoch/config/kind spellings.
Common decisions reuse literal decimal strings; variable backoff decisions
still require number-to-string. The unchanged whole-string stdout writer
requires one final exact-length substring. The compatibility frame function
continues to return the old numeric-fields/raw-kind/copied-prefix interface
for finite probes; the serving loop never calls it.

The private publication-pause hook still compares the raw kind spelling,
including leading zeros. Diagnostic gating is computed once at process start.
No GC switch, debt threshold or production runtime flag has been changed.

check-policy-allocation.py checks the explicit allocation sites and exercises
two rejection controls (injected concat and unbalanced syntax). It also parses
the Lisp produced by all twelve diagnostic modes without importing a runtime
runner. This is a source assertion, not a claim of zero interpreter allocation.

diagnose-policy-ipc.py --allocation-controls enables allocation telemetry only
in a finite diagnostic process with normal GC: debug-switch 24 resets/enables
counters; debug-switch 0 indices 10/11/12 report bucket reuse, linear reuse and
bump allocations. Each exchange records deltas and GC counts. Counter sampling
itself allocates and includes the input string, parser, writer and diagnostic
bookkeeping; compare identical before/after instrumentation rather than
interpreting this as an exact count of production objects. This telemetry
does not alter the authoritative uninstrumented policy budget measurement.
