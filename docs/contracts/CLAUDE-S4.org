* Authority and failure behavior
The five environment switches are DDSKK_HOST_POLICY_SOURCES, _CACHE,
_RESTART, _PUBLICATION and _LEARNING. Each defaults OFF; environment 1
enables, environment 0 overrides a selected-key registry DWORD. Corresponding
registry names are HostPolicySOURCES, HostPolicyCACHE, HostPolicyRESTART,
HostPolicyPUBLICATION and HostPolicyLEARNING. Restart the private host after
changing switches. No live settings were changed.

The worker uses a bounded, nonblocking native memo of pure managed answers.
Cold, stale, contended, saturated, oversized and failed decisions immediately
use the native fallback. The worker logs authoritative/fallback counts by kind
and exact timeout/discard IPC IDs. Timed-out signatures are invalidated;
crash/retirement invalidates all answers. Context is a fixed audit fingerprint,
not a semantic identity. The original source labels remain bounded native data.
One native transaction owner and one native storage pipeline remain in place.

Publication intent and payload decisions can publish base+overlay or overlay;
the existing native writer validates files and durable watermarks. The managed
policy returns SK1 hit/miss TTL durations and admission decisions. Native IO,
cache mutation, source byte loading/union, queue barriers, flush/replace,
outbox/FIFO, process jobs and mmap publication remain native.
