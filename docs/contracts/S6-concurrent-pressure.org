* Overlap proof and assertions

The receipt distinguishes armed-source envelopes from actual operations.
GC instrumentation, DNS fixture and periodic sharing refusal stay armed from
before deployment until after the cycle. Actual collection and file-handle
intervals are separate from those envelopes. During disconnected host intervals
there is no engine/policy process to collect; the storage and DNS fixtures
continue running. The request producer drains its current transaction before
an endpoint is closed and resumes on the next owned stack. No disconnected
interval is falsely reported as an actual engine/policy collection.

Four phase windows (deploy, traffic, rollback, cold-restart) require actual
network submissions, storage-handle intervals, engine collections and policy
collections. For each process in every phase, the checker requires a nonempty
three-way intersection of a completed collection, a storage refusal interval
and a network observation window. Network windows run from real submission
through the producer/ack sequence and at least 300 ms of observation; real
DNS packets and native cancellation are additionally mandatory. This is
periodic simultaneous pressure across all phases, not continuous collection
at every instant. Missing/disjoint intervals fail even when source envelopes
look complete. Cycle wall time over 1800 seconds fails.

The existing S4 callback checker is reused via its additive =-CheckLogOnly=
path for each warmed TSF log: import mask 271, >=10 probes, zero pipe IO and
blocking waits, the unchanged 20 ms callback watchdog, local conversion
branches, local ACK and no settle timeout. Existing exact main/peer document
and Emacs unchanged-buffer/render checks remain in the E2E fixture; concurrent
mode also checks exact warm-prefix plus four peer commits. Ordinary letter
latencies retain the existing <20000 us check. DNS drains retain <=1000 ms.
S4 =publication_gate= retains p99 <=500 ms and max <=1000 ms on actual native
policy-intent-publication samples; missing timing samples fail.

Each received LOCAL ACK is replayed twice after each stable lifecycle boundary
and again at cycle end, byte-for-byte. The recovered checkpoint must contain
exactly one local-ack marker per producer. Provider IDs must be unique and
the existing S4 =ack_gate= checks all sealed IDs against the final recovered
watermark. The bundle journal's authority must select the requested rollback
identity; the private registry pointers follow it. Real child PID/session-loss
checks and final recovered rows establish cold recovery. The existing
=host-test-process-guard.py= surrounds the gate, and Deployment.close verifies
owned handles exited. No pressure thread may survive cleanup.

* Coordinator deploy failure: connection ownership and fabricated checkpoint

Retained artifacts: =build/w/eh8-acb4c08a37a14a3285de2e8e0384900d/=.
=gate.log:17= records =AssertionError: b'ERR SESSION LOST'= in the provider
sequence; line 18 records empty guard leftovers. =cycle/host.log:4= has the
only child-start (PID 34484); lines 46, 49 and 53 are policy timeouts, not
engine replacements. =cycle/engine.gc:1= is the only completed collection,
1791636172.574646711--1791636172.751938581, before the deploy operation starts
at 1791636172.781891 in the concurrent receipt.

Root cause is the fixture's use of =Deployment.request= for every provider
SESSION command. That method opens and closes a fresh pipe for each request
(=private-host-bundle.py:81--91=). On disconnect, the host closes sessions
still owned by that connection (=windows/host/main.cpp:2764--2778=). If that
cleanup wins the race before the next pipe's V2 command, the engine correctly
returns SESSION LOST. OPEN was acknowledged on the right host; its owner then
disconnected. No product change is justified by this failure.

The provider OPEN/PREPARE/SPACE/COMMIT/CLOSE sequence now uses one persistent
pipe, independent of the asynchronous LOCAL LEARN pipe. Both pipes are closed
on failure and success. No retry or acceptance assertion is weakened.

Separately, =cycle/host.log:2= records learning-pending-recovery-failed, and
the retained =user.jisyo.eg2-checkpoint= is zero bytes. The storage driver used
OPEN_ALWAYS before startup, fabricating an invalid pending recovery file.
=LearningQueue::RecoverPending= correctly rejects an empty file. The driver
now uses OPEN_EXISTING and skips absent or busy targets, applying sharing
refusal only to files created by real durable work. The source remains armed
while a target is absent; absence is not recorded as actual storage pressure.

* Live reconnect/accept regression (2026-10-11)
The 71104ae selector fix published a fresh identity on every registry reload,
started one detached retry per publication, and disconnected on every retry.
This explains the reported singleton-loser storms following UI/core registry
writes. ConnectNamedPipe treated ERROR_NO_DATA (an already vanished client) as
fatal; error codes were not logged, so the exact codes in the historical live
failures remain unproven. No live settings or processes are touched by this fix.

Provider snapshots compare engine, EngineHost, EngineExecutable/NeLisp,
Repository, and the effective pipe by value. One serialized apply worker per
service retries with 100/200/400/800/1600/2000 ms backoff, without retaining the
provider mutex while sleeping, with a 60-second retry deadline. A configuration is
invalidated once, and later publications are applied before consuming keys.
A pipe-scoped inherited startup lease, the existing lifetime singleton, and a
process-wide five-second cooldown suppress duplicate launches. Busy/timeouts
never authorize launching another host. The inherited handle avoids detached
launch code executing after the core DLL is unloaded.

Certified native candidates are attempted before dispatch when selection is
pending or the cached connection is absent. A provider request attempts selection
with a short worker-only probe instead of spending its entire conversion budget
retrying a missing host. Failure retains the conversion and queued keys when no
certified candidate is available; it never acknowledges an unconverted reading.
Retained requests resume automatically after selection succeeds; the deadline
path also preserves queued keys and invalidates late replies. The normal
conversion budget and all existing checkers remain unchanged.
Transient ERROR_NO_DATA/ERROR_PIPE_NOT_CONNECTED/ERROR_BROKEN_PIPE accepts log
error codes and reuse the spare instance. Other accept errors remain fatal.
