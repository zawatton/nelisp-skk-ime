#+TITLE: Moving the DDSKK engine host to NeLisp
#+DATE: 2026-10-08
#+STATUS: DESIGN ONLY; implementation and qualification pending

* Decision and evidence boundary
Recommend option C: a separate NeLisp host-policy process behind a native
Windows adapter, continuing to supervise the existing engine as a separate
child. Keep the public host executable entry point and protocols compatible.
Move policy by responsibility, rather than replacing main.cpp in one step.
The adapter initially retains the existing native publication and durable
learning workers as well as transport and process ownership. This is a
strangler architecture, not a claim that the first adapter will be tiny.

Source baseline: main 96f1ecfdf25fc29b142df912f567f976c8155a4a. Source anchors
below refer to this checkout. Runtime anchors refer to the read-only sibling
../nelisp-ime; that tree and the specified runtime were not built or tested.
Source availability is distinct from availability in the deployed image.
No implementation, live deployment, registry update, or runtime experiment
is part of EH1. All numeric acceptance budgets below are proposed unless
explicitly identified as existing contracts or historical observations.

build/NC1-report.org:180 records Debian stop-the-world GC evidence; its
work-item table and ordered migration plan are the basis for this decision.
Reported pauses around 0.5--2.3 seconds and raw AOT kernels around 5--30 us
versus C around 0.3--6 us are not Windows measurements. Faster raw kernels
do not remove allocation, rooting, IO, or GC from general Lisp policy.
docs/design/local-first-conversion.org:1859 describes the durable provider
outbox closure; :2100 describes the interpreter/metadata lock split.
The historical provider plain SPACE <=40 ms target remains not met
(:2095); this design does not relabel that path as local or accepted.

* Architecture options and GC isolation
| Option | Advantages | Costs and reason for disposition |
|--------+------------+----------------------------------|
| A: host logic inside existing engine | One managed heap/process; internal calls can avoid host-to-engine IPC | GC stops policy and engine together; engine replacement also replaces transport; storage/network failures share DDSKK state. Reject as first move. |
| B: separate all-NeLisp host | Isolates engine from policy GC; simplest ownership in Lisp | Still needs qualified named-pipe/security/durability/job bindings; cached host commands and publication pause with host GC. Useful eventual target, not established today. |
| C: separate NeLisp policy plus native adapter | Isolates both managed heaps; preserves proven external OS boundaries and unchanged clients; permits per-responsibility rollback | Extra IPC, two managed startup/heap costs, initially substantial adapter. Recommended until OS1 and VAL1 qualify replacements. |

Topology (proposed): TSF core -> mapped base/overlay on local SPACE; TSF
provider worker or Emacs -> native public pipe adapter -> NeLisp policy ->
existing NeLisp DDSKK engine. Adapter owns both children in its Job Object.
Policy selects sources, cache/restart decisions and publication intents;
adapter owns handles, verified immutable bytes, stable generation/epoch
numbers, journal IDs, flush/replace barriers, cached public replies and
bounded queues. Initially the adapter also owns the SK1 worker and learning
FIFO; moving those algorithms requires independent qualification.

No native IO callback enters Lisp. Exchange copied, bounded messages with
explicit request ID, child epoch and publication generation over a private
channel. Never share moving Lisp pointers or Lisp-owned mutexes with native
IO/publication workers. Retain one interpreter transaction at a time; a
policy event loop is sufficient, and concurrent Lisp execution is unnecessary.
Cap queue bytes and requests; isolate maintenance from relay scheduling.
On policy pause, the adapter serves immutable cached replies and keeps old
mapping generations. It does not synchronously consult policy for local
conversion, publication of an already validated intent, durable append or
timeout/cancel. Uncomputed policy results can be stale, not magically fresh.
After timeout, drain/discard the matching reply or replace that channel;
never let a late response satisfy a later request. Reconcile durable IDs
before replay. Non-idempotent session editing is not blindly retried.

The local guarantee is conditional on an already published valid dictionary
and supported/certified local feature. SPACE, candidate navigation, local
commit/cancel and reading edits use core state and mapped bytes. Learning
enters the core's background durable spool. Mapping refresh/publication and
network enrichment are background work. No host/engine lock, pipe wait, TCP,
flush, GC or policy allocation may occur in the TSF key callback. If a mapping
is absent or a feature needs DDSKK (registration, expressions, complex edits),
the provider worker handles it asynchronously; this is a different latency
class. Ordinary keys must continue while that worker waits. Preserve callback
ownership and stale-result guards, rather than invoking a synchronous fallback.
Emacs provider conversion can wait for its worker/service; it does not inherit
the core's local guarantee merely because the host was rewritten.

DNS resolution, slow disks, hostile clients and queue saturation are explicitly
outside the unloaded percentile fixture but inside cancellation/recovery tests.
Native supervision must enforce finite work deadlines despite Lisp pause. Under
saturation use existing PENDING/miss/error semantics where defined; otherwise
close a failed transport and let existing recovery handle it. Any new BUSY or
capability reply requires explicit version negotiation, not a silent wire edit.

CW1 builds the offline Win64 application closure; CW2 qualifies typed adapter
entries without unrooted pointers. RW1 matters only if embedding/reentrant
foreign Lisp callbacks are introduced; avoid that in C. RW2 applies to future
raw index kernels; mapped dictionary bytes must remain outside the Lisp heap.

prerequisite for promising tighter managed service tails. RW4 reduces the two
managed processes' startup/memory cost. OS1 is the migration's blocking work.

host; preserve native core/shim ABI and existing generation leases. VAL1

Retiring a native adapter component requires OS1/VAL1 evidence for that exact
contract, not just fboundp, successful import, or a raw kernel benchmark.

* Protocol and storage freeze
Freeze public message-mode pipe semantics, CLI ENGINE_EXE [REPOSITORY], env and
private-registry overrides, error tokens, UTF-8/codepoint conversion, STATE/STATE2,
WIRE UTF8 1, WIRE LEARNING 2, LEARNING2 byte framing, LOCAL commands, scoped
SESSION OPEN 2 / V2 / PREPARE / SPACE / LOST recovery, legacy negotiation and
CONVERT-KEYS. Freeze local-index versions, capability refusal rules, base/overlay
layout, current manifest, lease cleanup and producer spool/outbox/checkpoint/
watermark formats. Unknown capabilities keep legacy behavior. An internal
adapter-policy protocol gets its own version and size bounds; it must not leak
onto the public pipe. Build a fixture manifest with bytes and hashes in S2.

Preserve three distinct orders: durable producer intent before provider STATE;
FIFO checkpoint plus durable operation metadata before LOCAL ACK/retirement;
immutable index bytes before current manifest publication. A candidate revision
may publish before the checkpoint, but its durable watermark must not. Do not
confuse volatile session checkpoints with durable dictionary checkpoints.
One storage writer/ID authority survives policy restart. Validate incoming
intent content but choose paths only from trusted configured roots. Do not let
wire input choose a temporary file, spawn command or privileged mapping name.

* Migration and end-to-end acceptance
Every stage below ends with a real end-to-end criterion. EH1 only completes
the written specification checks; even S1's end-to-end baseline gate remains
pending. Existing tests are reused without lowering thresholds. A later
implementation lane must first reproduce any newly identified failing gate
on its unchanged tree. Here no failing behavioral check was supplied.

** S1: design and unchanged-native baseline
Inventory caller deadlines/config/ACL consumers and pin source/runtime hashes.
Run native baseline in private registry/pipe/data roots, with the exact supplied
runtime parameter, cold wait 45 s and first lattice warmup

** S2: freeze interchangeable external contracts
Capture byte fixtures and semantic oracles for every request class, old/new
engine negotiation, malformed/truncated UTF-8 and partial transport. Audit
caller total versus per-transfer deadlines and client cancel behavior. Add
private pipe soak: 32 clients, 100,000 completed requests, fragmentation,
squatting clients, abrupt disconnect, queue saturation and endpoint collision;
zero cross-session replies, lost accepted durable IDs or leaked children.
End-to-end: unchanged native binary runs the frozen corpus through both TSF
and Emacs paths plus private SK1 and session-v2 tests. Adapter cannot advance
until it passes the same corpus, not merely a new parser unit test.

** S3: adapter and shadow NeLisp policy
Factor native contracts without changing public behavior. Shadow policy consumes
copied events and proposes cache/source/restart/publication decisions; native
remains authoritative and the shadow cannot write a second learning journal.
Fault inject policy crash, malformed intent, 3 s GC pauses and channel overflow.
Measure native/managed private memory and warm/cold startup. End-to-end: adapter
with shadow policy passes baseline TSF + Emacs + durability + soak while local
keys continue during repeated policy pauses. Reject on callback wait or stale
result adoption. Shadow parity is semantic, not identical wall-clock order.

*** S3 implementation (EH3, 2026-10-08)
The existing executable, arguments and public endpoint/protocol remain the
native adapter. =windows/host/native_adapter_transport.h= factors its engine
process handles and bounded stdio reader/writer out of main.cpp. Native IO,
cached responses, local publication, durable files, learning FIFO/outbox, SK1,
interpreter ownership and the kill-on-close Job Object remain native. No core,
shim, settings or dictionary file is changed by this stage.

=windows/host/native_adapter.h= adds a separate native supervision thread and
value queue. =DDSKK_HOST_POLICY_SHADOW=1= enables it; absent/other values leave
it disabled. The same runtime argument launches =engine/host-policy.el= with
=--load= in the supplied repository. The child is started suspended, assigned
to the adapter job, then resumed at below-normal priority. Its inherited
handle list contains only private stdin/stdout (stderr shares stdout); public
pipes, engine handles and storage handles are not policy IPC capabilities.
Startup/exit/ready/comparison/timeout/drop diagnostics stay on native workers.

HP1 is documented additively in =docs/contracts/policy-ipc-v1.json=. It has a
4096-byte frame cap, 1024-byte copied context cap, 64 queued value objects and
a 128 KiB queue byte cap, plus one outstanding request. Requests carry a
monotonic request ID, policy epoch, actual engine child epoch and diagnostic
publication generation. Active-child epoch changes at the native swap, not
when a warming child starts; publication snapshots copy their epoch while
holding native metadata ownership. All identifiers and kind must match the
reply envelope. No Lisp pointers, evaluator input or shared Lisp locks cross
this boundary. Queue contention/full/oversized context drops observations,
never native requests or acknowledged operations.

The ready deadline is 60 s, the reply deadline 200 ms. A timed-out request
keeps sole ownership of its channel for a bounded 5 s late drain; its matching
late reply is discarded. Bad version/envelope/type, child death or drain
expiry retires the channel before another request. Policy launch failures
back off from 1 s to 30 s; a ready child resets supervision backoff. Host
shutdown interrupts polling and joins supervision, including early returns.
Detached native clients retain a process-lifetime observation queue/mutex.

The policy independently computes runner fallback, ordered source-tier choice,
native replacement backoff, hit/miss TTL expiry and publication readiness
from copied inputs. Engine/source identity strings are copied as bounded UTF-8
hex context. Native cache admission/eviction, source reading, publication
coalescing, durable barriers and engine transactions are retained; HP1's
publication =c= field is the native window's due input, not a port of that
window algorithm. Responses only produce match/mismatch diagnostics. They
cannot answer public clients, publish mappings or emit learning. This is S3
shadow observation, not S4 authority or full policy-algorithm migration.

*** S3 qualification and coordinator commands
=run-engine-host-s3.ps1= supplies Boundary, Isolation, Contracts and EndToEnd
stages. Boundary builds a separate test control executable and tests queue
caps/copies/contention, stale IDs/epochs/generations and malformed envelopes.
It runs policy ERT and the exact Windows image's HP1 probe (split/batched
frames, six decisions, five malformed inputs and a Lisp-side 3 s pause).
The supplied image has =float-time= but lacks =sleep-for=; the private Lisp
injection blocks only the policy event loop using its clock. That limitation
was reproduced rather than inferred from GNU Emacs.

Isolation suspends only a verified job-owned policy child for 3 s, forces a
real source observation, checks 801 cached requests with unchanged unloaded
p99 <=10 ms/max <=50 ms limits, and requires a real durable LOCAL LEARN overlay
publication during the pause (<=1 s). It verifies late discard, kills policy,
checks cached service and restart, and records host/engine/policy private
bytes, handles, policy startup times and owned PIDs. The unchanged S2
32-client/100000-request/20-control soak runs during a policy pause and kill.
Every spawned child is job-owned and cleanup waits for observed child PIDs.
The separately compiled synchronous control waits on the real policy channel
inside ServeClient. The identical isolation gate must reject it with observed
cached latency >50 ms and confirm no leftover child, not just exit nonzero.

EndToEnd enables =DDSKK_HOST_POLICY_TEST_PAUSE_KIND=5= for repeated Lisp-side
3 s pauses on publication observations. Injection requires diagnostics and a
private =Software\NativeIME-test-= key. Existing local callback/watchdog,
publication/learning, real SKK-JISYO.L stress and Emacs/inline tests retain
their original thresholds. It removes that injection before the independent
OS-suspension/kill gates. TSF/registry/real Emacs acceptance is a coordinator
gate, not inferred from ERT or pipe-only results.

* Risks and open questions
- The exact runtime image may omit OS helpers visible in source. Qualification
  must use the supplied Windows artifact and list loaded modules and identities.
- Default named-pipe security is not an explicit least-privilege contract.
  Which low-IL/AppContainer clients and Sumi state-map ACLs must be supported?
  Test current access first; tightening ACLs requires compatibility evidence.
- Two managed heaps increase memory and cold startup (13--45 s engine load).
  Measure private bytes and warmup, including both processes, before AOT work.
- Threads accepting native entry pointers do not establish Lisp thread safety.
  Keep adapter callbacks independent; embedding would reopen RW1/CW2 risks.
- DNS and detached blocking client IO have weak shutdown bounds today. Adapter
  cancellation must improve boundedness without changing public message semantics.
- Storage flush/rename reliability depends on filesystem and device behavior.
  Crash tests establish the supported local Windows filesystem contract, not
  power-loss guarantees on arbitrary network shares or dishonest devices.
- Policy GC may delay fresh source/config intents even if cached reads and
  existing mappings continue. Distinguish service freshness from key latency.
- Host restart can lose volatile provider composition; session restoration and
  pending edits need exactly the current client recovery rules and focused tests.
- Are all Emacs/Sumi cached requests suitable for native cached replies? Freeze
  state-owner/PID/version rules before moving publication policy.
- Queue byte limits, fair scheduling, soak resource ceilings and supported storage
  fixture must be pinned in S2. Never discard acknowledged durable operations to
  meet a queue limit or percentile budget.
- Legacy learning engines still require interpreter snapshots and their own
  synchronous writer. Preserve fallback until their retirement is explicitly scoped.
