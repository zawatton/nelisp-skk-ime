#+TITLE: Local-first DDSKK conversion: design and LF1 measurements
#+DATE: 2026-10-06

* Decision and scope
The TSF core should own ordinary conversion: reading construction, dictionary
lookup, ordered candidate traversal, cancel and document commit. It reads an
immutable shared memory-mapped dictionary generation and a small user overlay.
No ordinary conversion or subsequent key waits for the engine. NeLisp DDSKK
remains an asynchronous learning/registration/advanced-feature service. Emacs
is an optional inline display consumer, never a required engine process.

LF1 changes only this design, the S1 ledger and windows/proto. The prototype
is not connected to windows/CMakeLists.txt or any DLL. It establishes lookup
cost, not DDSKK state-machine equivalence or the S2.3 <=30 ms target.

* Search source split
Stock skk-search-prog-list in vendor/ddskk/skk-vars.el:438 contains the
following sources in order. The core must carry an explicit source plan,
not assume every installation has only one large dictionary.

| skk-tankan-search wrapping large jisyo | Engine: radical/stroke/special @ search |
| skk-search-jisyo-file initial jisyo | Local optional indexed tier in configured order |

| skk-search-jisyo-file large jisyo | Local shared mmap tier |
| skk-search-server aux large jisyo | Local imported snapshot where available; remote/network-only sources asynchronous, engine fallback when required |
| skk-search-ja-dic-maybe | Engine until compatible adapter exists |
| skk-search-extra-jisyo-files | Local indexed files, preserving their concatenation and filtering behavior |
| skk-search-katakana-maybe | Local generated terminal tier after dictionaries, enabled only by matching setting |
| skk-search-sagyo-henkaku-maybe | Engine initially; special conjugation |
| skk-search-itaiji | Local indexed special tier after matching its single-character guard |

The current engine replaces this entire default list with
ddskk-user-jisyo-search then ddskk-engine-server-search; optionally
skk-search-katakana-maybe is appended. The host shared tier merges configured
DictionaryFiles in first-occurrence order, then can relay to a configured
server. These current supported sources are the initial local scope.
Uninstalled stock features must not be advertised as supported already.
Alternate numbered search lists and arbitrary Lisp search/end hooks require
the engine unless the exported configuration explicitly certifies a local
equivalent. A finite capability digest selects the path before conversion.

** Candidate order, identity and laziness
skk-search stops at the first nonempty source and advances
skk-current-search-prog-list. skk-henkan-1 asks further sources only when
necessary, unioning results with skk-nunion. Therefore a flattened eager
union can be cached internally, but the visible frontier and source exhaustion
must remain DDSKK-equivalent, including when the candidate menu opens.
Space/next/previous/page/select and Enter operate entirely on the pinned
local candidate state. Exhaustion starts registration only after all enabled
sources are actually exhausted; an unavailable source is not a miss.

Store raw candidate identity, displayed word and annotation separately.
DDSKK union uses equal on the full values; the current host shared merge
deduplicates the word before ';' while preserving the first annotation.
These are different policies at different boundaries. Preserve them explicitly
in the current-engine compatibility plan; use stock DDSKK as the final oracle,
and document any deliberately corrected current-engine difference.
Do not insert ';annotation' into the document. Lisp-expression candidates,
ignored-word expressions and hooks are engine features; never evaluate them
as native code or display their source as an ordinary word.

* Okuri, modes and input behavior
** Okuri-nasi and okuri-ari
An okuri-nasi key is the completed reading. An okuri-ari key combines the
hiragana stem and roman okuri discriminator, e.g. KaKu -> かk with resolved
okuri く. The uppercase boundary and rule tree, not a guessed last byte,
determine that key; ASCII abbrev readings must carry a separate mode flag.
Do not normalize kana, punctuation or Unicode beyond DDSKK's actual rules.
Retain stem, okuri letter, resolved okuri, pending prefix, raw input and
editing/cancel policy independently. Complete okuri can trigger conversion
without Space; another Space advances candidates rather than reconverting.

SKK entries retain plain fields and each [okuri/candidates/] block.
Stock skk-select-words-from-list returns only matching-block candidates
when skk-henkan-okuri-strictly is true; with strict-okuri-precedence it unions
matching candidates before plain ones; otherwise it returns plain candidates.
Missing blocks, cancellation retaining/deleting okuri, Backspace inside an
unresolved okuri prefix and automatic conversion must all follow the oracle.
Current host MergeBuiltinCandidates and user --plain-candidates discard
blocks. Consequently today's strict toggle cannot reproduce stock block
ranking. The future index preserves blocks; LF1 raw views already preserve
them, but its PlainCandidates intentionally does not implement ranking.
This discrepancy must be fixed in coordinated engine learning/export too,
otherwise later compaction would erase locally preserved ranking.

** Numeric conversion
Stock skk-num-compute-henkan-key normalizes fullwidth digits, strips grouping
commas and replaces numeric runs (optionally decimal runs) with '#', keeping
the original numeric list. skk-search can union exact and numeric searches
for numeric-enabled programs. Candidate templates support #0 unchanged,
#1 fullwidth, #2 digitwise kanji, #3 positional kanji, #4 dictionary relookup,
#5 financial kanji, #8 grouping and #9 shogi. Template/raw identity is distinct
from displayed expansion. Numeric learning can use the normalized template
key; #4 also has numeric-key update semantics (skk-num-update-jisyo).
Implement pure expansions locally only after stock-oracle coverage, retaining
leading zeros, multiple runs, decimals, large numbers and annotation behavior.
Initially route numeric features, recursive #4 and expression candidates to
the engine. An exact mmap lookup is not numeric conversion support.

** Abbrev, katakana and rules
Abbrev starts with '/' and uses the abbrev keymap; lookup must retain the
literal ASCII key and mode (case, digits and punctuation included). It must
not accidentally romaji-convert or classify Latin keys as okuri stems.
Ordinary katakana mode and q toggles stay in RealtimeFrontend. Katakana
candidate generation is a distinct last search source, gated by the setting;
it must not preempt an existing dictionary candidate.
Use the engine-exported rule tree/profile and settings digest. Preserve n,
nn, n', carry/remainder, doubled consonants, punctuation, z sequences and
custom rules. Persist a last-known verified export so ordinary typing and
conversion work without a running engine. Unknown rule/profile digests route
unsupported commands explicitly; do not silently substitute default romaji.

** Registration
Empty confirmed search or candidate exhaustion opens the engine registration
editor. Send one explicit handover containing session/context epoch, reading,
mode, okuri, raw input, candidate frontier and selected identity. The future
protocol needs state import; today's ConvertKeys replay is a compatibility
fallback, not an asynchronous learning operation. Registration remains modal
and can nest; cancellation restores the pre-registration reading/candidate
checkpoint. Registration commit returns a validated candidate plus a learning
delta, updates the local overlay and commits once. New local conversions need
not await unrelated registration or learning in another application.

* Shared index and publication
** Proposed production format (not yet implemented)
Use fixed-width little-endian offsets, never process pointers, with magic,
schema, file length, generation, source/config/rule digests, source content
hashes, checksum and build completion marker. Sorted UTF-8 key table points
to source-specific candidate vectors and a string pool. Candidate records
retain raw word/template, annotation, source rank, flags and typed okuri-block
vectors. Keep user ranking as its own generation/overlay; do not bake its
priority into an unchangeable shared list. Reject unknown versions, overflow,
out-of-bounds/overlapping sections, malformed UTF-8 and incomplete publication.
Builder parses source files off the keystroke thread. Record bad-line counts;
never silently treat a missing dictionary as an empty successful generation.

Build a new uniquely named file, flush, validate, then atomically publish a
small manifest. Readers open read-only with delete sharing, pin the mapping
for a composition, and map the next generation only at a safe boundary.
Old mappings remain valid until their final reader releases them. No in-place
editing under readers; cap generation retention and validate file access
permissions. Mapped pages are shared through the OS cache across app processes.
Measure private bytes separately from mapped bytes and working set.

** LF1 experimental format
windows/proto/mmap_index.h defines a 32-byte header (magic/version/count/size),
48-byte sorted record (offset/length pairs for key/user/shared) and UTF-8 raw
payload. Read-only CreateFileMappingW/MapViewOfFile, binary search, zero-copy
Hit views; caller must retain Index lifetime. Open validates header, bounds
and strict key order. Build preserves raw annotations/blocks and duplicate
key last-wins behavior. PlainCandidates drops block fields and exact-unions
user before shared. It handles one shared source only; no checksum, content
digest, UTF-8 validator, durability/manifest publisher or ranking protocol.
It is not a distributable dictionary or production-safe index format.

* Learning and cross-process consistency
Stock skk-update-jisyo-original moves the confirmed word to the front, updates
matching okuri ranking blocks and history, handles numeric template keys,
and records shared-personal updates. Purging a shared word can install an
ignored-word expression; merely deleting the local word does not suppress
the shared result. Current ddskk-user-jisyo--update is narrower: cleans the
full candidate, exact-equal move-to-front by skk-henkan-key, append of the
whole changed entry to .journal; purge removes it and immediately flushes;
compaction writes the base before truncating the journal. It drops okuri
blocks on load. Existing journal behavior is useful, but not a stock-parity
specification. The design must migrate storage/export with explicit schema
and stock-oracle tests for okuri, purge tombstones and numeric learning.

Document commit is immediate in the core. Add a pending in-memory learning
delta so a second conversion in that same client sees its just-confirmed
word first. Enqueue LEARN(session, epoch, unique operation id, generation,
key, okuri, raw candidate/template, display word, action). The engine is the
single writer and orders operations globally, journals them durably, then
ACKs with an authoritative sequence and changed-entry delta. At-least-once
delivery must be idempotent; the acknowledged operation-id watermark must
survive restart. Never infer confirmation by candidate index alone.

Publish the new overlay to all clients; fold pending deltas over the confirmed
generation until their ids are acknowledged. Concurrent same-key learning
uses engine sequence order. Purges and registration are explicit operations.
A composition pins its candidate list even when another app learns a word;
apply new ranks on the next conversion. Late ACKs cannot rewrite committed
text, move a selection or revive an expired context. Engine failure leaves
ordinary input usable; bounded queued learning and an explicit unsaved status
avoid claiming durability that did not occur. A protected local spool is
needed for crash-safe pending learning; implement it off the TSF thread.

The engine must not maintain a shadow local-key stream and later replay it
one key at a time. Supported local conversions own their complete state.
Engine calls for unsupported commands use an explicit epoch-tagged handover
barrier. A late fallback response applies only to that barrier's live context.
Engine responses/learning ACKs carry no authority over a newer local session.

* Document and inline channels
Produce one core state snapshot for candidate UI and document edits. Obtain
the TSF edit session to replace the reading/okuri range and commit synchronously
when permitted; preserve existing edit-session failure handling and caret
identity. New keys update local state directly, without provider waiting and
per-key replay. Closing/switching context invalidates UI epochs and callbacks.
InlinePreedit already publishes snapshots on its own socket worker with epochs.
Use the same local state there; inline socket/listener delay cannot block input.
Candidate caret placement and Emacs rendering are presentation consumers.
Missing/wrong/disconnected listeners retain existing TSF fallback behavior.

* Failure policy and rollout
- Missing/corrupt index: keep last verified generation; otherwise explicitly
  choose the existing private-engine path before displaying a candidate.
- Not-yet-built/user-overlay-not-ready: do not claim a dictionary miss or
  open registration; keep the reading and offer fallback/unavailable status.
- Engine down: local ordinary conversion and commits work; learning is
  pending, registration/unsupported commands report unavailable.
- Unknown hooks, numeric/expressions/advanced sources: select engine ownership
  before conversion; timeout/cancel leaves editable reading, never duplicates
  a document commit. Remote-source replies cannot reorder visible candidates.
- Resource limits: no file build, full mapping validation, network access,
  unbounded candidate expansion or journal compaction in a key callback.
- Rollout: S1 prototype -> private ordinary-conversion oracle -> okuri/modes
  -> asynchronous learning/registration -> private TSF and real Emacs inline
  latency/typing-ahead gates -> opt-in production setting -> user-approved live
  deployment. LF1 does not create settings, deploy or register anything.

* LF2 ordinary production slice (2026-10-06)
This implements the ordinary portion of S2.1 and starts S2.3. Okuri-ari,
numeric/expressions, additional search sources/hooks and registration stay
with the provider. No shim or exported core ABI changes; no live deployment.
LocalConversion DWORD defaults to 0. Apps/<executable>/LocalConversion may
override it with 0/1. The engine host starts publication when any application
opts in. Its source plan matches the provider's active DictionaryFiles;
source configuration changes require the normal host reload.

The production schema is separate from LF1's experimental format: 144-byte
header, 48-byte sorted records, SHA256 configuration/content digest and whole
generation checksum, bounded UTF-8 sections and a validated rule export.
The LF2 host parsed sources plus an engine overlay snapshot into each full
generation. LF5 replaces that publication format with the split below.
Protected user/SYSTEM ACLs and owner checks apply.
The core worker validates new mappings; key callbacks never build or fully
validate a generation. A composition pins its candidate list and rules.

Supported ownership is selected before SPACE conversion: completed hiragana,
plain candidates, certified personal-then-built-in source plan, external
server disabled. User candidates retain their lazy source frontier. Shared
file merging retains first word/annotation priority; personal/shared union
uses stock DDSKK's directional annotation equality. Missing generations,
uncertified plans, misses and oversized entries use the provider. The core
handles SPACE/x, cancel, explicit and implicit commit synchronously, including
inline rendering; subsequent typing stays in the same native key callback.
Candidate exhaustion crosses one explicit registration barrier.

Learning uses a separate engine client and bounded 256-operation queue. A
full queue chooses provider ownership before the next conversion rather than
discarding a confirmation. Pending deltas affect the next conversion
immediately. The worker flushes an atomic per-client spool and reclaims only
unowned/crashed-client spools. Client operation watermarks share a verified
checkpoint with candidate order. The engine writes a temporary checkpoint;
the host flushes it and atomically replaces the configured personal jisyo
before ACK. Later compaction preserves the same atomic checkpoint. Global
ACK sequence versus overlay sequence retires deltas even if publication
preceded ACK receipt. Learning failure stays pending; diagnostics expose
queued/pending/ACK/unsaved counts. Persistent user-facing unsaved indication
and broader storage/recovery stress coverage remain follow-up work.

* LF5 split publication (2026-10-07)
Schema 4 retains the 144-byte header and 48-byte record layout. A
=generation-*.index= contains configured source tiers, rules and capability
certification, with overlay sequence zero. An =overlay-*.index= contains
only the engine's user snapshot: learned rankings, registrations and okuri
blocks, together with its durable ACK sequence. Its metadata names the base
file and its header repeats the base configuration digest and capabilities.
=current= atomically selects the overlay, so readers cannot combine an
overlay with an unrelated base. Nested base references are rejected.

The host caches source metadata and a verified base. Source metadata changes
trigger content hashing; unchanged content reuses the base. Rules or
capability changes rebuild it. Host restart verifies current and reuses its
base when the content digest agrees. Overlay publication parses, hashes,
flushes and validates only the overlay against that pinned base. Directory
collection runs separately, once per second. Each client reuses its existing
base mapping while replacing the overlay. Composition ownership still pins
its candidate list and rules; rule ownership follows the base generation.
Lookup composes the same certified user/shared tiers as the baked format,
including annotations, source order and unsupported-entry sentinels.

Learning ACKs retain their checkpoint-before-ACK behavior. ACK activity
wakes the publisher; a window anchored at the first dirty ACK collects
changes for 200 ms. Idle status discovery remains once per second. Initial
publication and source/rule/capability changes bypass the window. Pending
client deltas continue to affect lookup until a verified overlay covers
their ACK sequence, including an ACK received after that overlay was mapped.

Readers retain file handles without delete sharing. Collection attempts to
remove every superseded generation, overlay and incomplete manifest; files
still pinned by a client survive until a later sweep. Startup repeats this
collection. If collection races a client opening a selected filename, the
client keeps its previous verified mapping and retries once per second,
even when current's timestamp is unchanged. The host exclusively claims
exited-process spool leases and
replays their records through durable idempotent learning before deleting
queues and locks. Unreplayable records are retained. Live processes are not
reclaimed by the host. Core workers may transfer released same-process
leases during hot swap. Empty retired queues are removed on worker exit;
nonempty queues retain their per-client identity and recovery semantics.

* SK1: asynchronous external skkserv sources

File and user candidates retain the local input path. Enabling SkkServ no
longer removes the certified local capability. SPACE (or completed okuri)
queues an immutable reading+okuri request in the core Store. A separate
core worker polls a host-only LOCAL SERVER message; no engine session,
shim ABI, socket operation, file scan or provider transaction is involved
in the input callback.

The host ServerCache owns external sockets on one joined worker. It holds
at most 256 entries and queued requests, with replies capped at 64 KiB.
The key includes reading and okuri. Host, port, enable, dictionary source
paths and start command form a configuration generation; config changes
clear queued/cache entries and reject old in-flight results. Hits expire
in 60 seconds, misses in 2 seconds. Connect is nonblocking with a 150 ms
bound per resolved address; send+receive share a 150 ms deadline. DNS
resolution stays on this worker (OS resolver latency is not bounded by
the socket deadline).

The core polls every 50 ms with overlapped pipe transfers bounded to
100 ms per transfer. It merges certified literal server replies after
all user/pending/file candidates, using existing stock union semantics.
The open candidate list updates without changing the selected word.
Disabling the server removes its appended tier and clamps a removed
selection to a remaining file candidate. Pending traversal retains the
last file candidate for at most 250 ms; the UI timer advances with the
original next/menu operation or invokes the existing provider registration
barrier. Any intervening input cancels pending advancement.

A reading without local candidates uses the existing asynchronous provider
conversion. Its relay enqueues the external lookup and waits at most 200 ms
before returning a miss for stock registration. Provider lookup now unions

** Protocol and ownership
=SESSION ID OPEN 2= negotiates =OK OPEN 2=. Version 2 editing requests use
=SESSION ID V2 REQUEST=. Unopened, evicted, and replacement-created v1 records
answer =ERR SESSION LOST=; they cannot silently substitute an empty composition.
=CLOSE= releases the buffer. At most 64 records are retained, with LRU eviction.
Existing SESSION/v1 requests remain supported.

=PREPARE 2 decimal-keys= feeds only a new reading suffix. A non-prefix edit uses
a clean replay. =SPACE 2= carries no reading and converts the installed state;
it preserves automatic okuri conversion instead of advancing it. =CONVERT-LIVE
2 decimal-keys= is the full-reading recovery barrier. The core coalesces ordinary
provider preparation on a background thread; the existing local-conversion path
keeps its existing behavior. Focus abandonment invalidates preparation and uses
the existing scoped reset contract. It does not resume abandoned TSF compositions.
A per-client transaction mutex prevents preparation/control wire interleaving.

The core retains only uncommitted recovery requests. Explicitly acknowledged
commits clear that history; an implicit commit boundary prevents automatic replay
of old confirmed text. The existing core full-reading recovery handles that case.
An old engine rejects OPEN/V2, and the core uses SYNC/CONVERT-KEYS replay instead.
The direct pipe client test covers eviction/loss and downgrade during navigation.
The shim export/import structures and ABI are unchanged.

** Learning, ordering, and durability
The host negotiates =WIRE LEARNING 2=. Ordinary learning still updates DDSKK's
in-memory order immediately. The engine captures complete rows for changed
readings and only the changed operation watermark. =LEARNING2 scalar-count=
is followed by a bounded raw UTF-8 frame. No learning write/save/flush executes
in Lisp after negotiation. Older hosts/engines retain their original writer.

One native worker merges row fragments, preserves candidate/okuri ordering and
operation ids, writes a private checkpoint, flushes it, atomically replaces the
configured user file with write-through, and clears the superseded journal.
FIFO order and immutable row snapshots preserve at-least-once operation retries.
The native cache is invalidated at engine publication to include fresh legacy
learning. Shutdown drains the worker. Storage failure is not acknowledged.
A checkpoint identifies the legacy journal it supersedes by scalar count and
exact scalar encoding; startup skips that journal only on a match. A fresh journal
written by an old engine is replayed. The Emacs regression and native cache
replacement test cover both cases.

The engine transaction mutex is released before a caller waits for durability.
A blocked injected worker leaves that mutex available; the native suite verifies
this, FIFO order, actual checkpoint bytes, failure, and shutdown drain. Replacement
startup waits for the current storage fence outside the transaction mutex and
retries if learning changes during cold loading. Explicit idle GC uses try_lock
and refuses to start while requests are queued. An already-running GC still
cannot be preempted. In-memory revisions continue to wake the overlay publisher.

Strict immediate commit replies are NOT implemented: the host still waits for
that request's durable checkpoint before returning STATE/ACK. Concurrent commits
can wait on the FIFO worker. This deliberate durability barrier is a remaining
EG2 acceptance gap. Overlay snapshot serialization also still runs in the shared
engine; the TSF/overlay gates below could not execute in this sandbox. A fully
asynchronous durable intent/spool boundary is still needed to remove the reply
barrier without acknowledging volatile learning.

** EG2 follow-up: immediate state, independent publication, SPACE floor
This follow-up supersedes the earlier EG2 delivery numbers and the statements
that every reply waits for durability or that v2 overlay snapshots run in the
interpreter. Changes remain unstaged. Acceptance remains open for the strict
provider-learning crash window, the plain SPACE target and registry gates.

STATE replies return after the interpreter has finalized the in-memory session
and enqueued immutable learning rows. They do not wait for storage. LOCAL ACK
still waits outside the engine mutex: it is the existing durable producer-spool
retirement signal. The FIFO worker merges rows, writes/flushed a complete private
checkpoint, atomically replaces the dictionary, and clears only its incorporated
journal. Transient failures retry the same head job; shutdown stops retrying
permanent failures and drains queued jobs. A complete staged checkpoint includes
candidate order, revision, operation ids and an exact length footer. Startup
validates and reflushes it before publication and engine loading. Torn stages
are rejected. These guarantees cover durable stages and LOCAL spool replay.

There is an explicit remaining limit: a normal provider STATE reply can precede
the worker's first durable write. Abrupt host loss in that interval can lose
provider learning, because that producer has no durable outbox/operation id.
The staged-crash test does not cover that interval. Immediate STATE is not a
durable learning acknowledgement. Strict crash-safe at-least-once learning for
all such commits requires a producer outbox/protocol extension; it is not proven
or implemented by this queue. Do not mark requirement B fully accepted.

The publication thread now owns a native row mirror. It copies capability and
rules metadata briefly under the engine mutex; dictionary reads, merges, full
snapshot encoding, source metadata checks and publication occur outside it.
Spool recovery runs on a separate maintenance thread, so its durable ACK wait
cannot stall overlay publication. Candidate fragments publish before storage;
operation watermarks publish after storage. The current client also requires
a pipe ACK before retiring its spool. Publication generations ensure that the
later durable watermark republishes at the same learning revision. Disabled
local conversion consumes mirror fragments once a second without full encoding.
Legacy engines retain the previous snapshot/writer route and negotiation fallback.

SPACE preparation caches the modal checkpoint and state; keyless SPACE takes no
new checkpoint and real conversion takes one result snapshot. Editing invalidates
the cache; registration/repeated SPACE preserve modal behavior. A literal
char-after predicate replaces the stock marker regexp only on NeLisp, preserving
stock edits, undo suppression, errors, point and mode. GNU Emacs retains stock
DDSKK. Stock search/eval/source hooks remain intact: a direct-provider-call
experiment gave no reliable benefit and was removed. Session ids now include
a QPC nonce to avoid DLL reload address/counter reuse. LRU/loss/restart fallback
and old-engine downgrade remain tested.

** EG2 durability closure: durable provider outbox (2026-10-08)
This section supersedes the preceding provider-learning crash-gap limitation.
Provider learning is durably recoverable before STATE is sent. Overall rollout
acceptance still awaits Claude's registry-dependent gates. The user explicitly
accepts documenting plain SPACE <=40 ms as not met: retain the measured
57.001050 ms learned / 70.592750 ms first-conversion p50 and the preceding QPC
attribution. The new small burst run is not a replacement floor measurement.

A learning frame reserves a monotonic provider operation id and FIFO position
under engine ownership. After interpreter dispatch releases the engine mutex,
the reply path appends a versioned, bounded, checksummed record containing that
id, complete changed rows, candidate order and learning revision to
=user-jisyo.utf8.eg2-outbox=. FILE_FLAG_WRITE_THROUGH plus FlushFileBuffers must
succeed before any provider STATE reply containing that learning is sent.
Append failure returns =ERR LOCAL STORAGE= and prevents worker publication of
that job; partial failed appends are rolled back, and failed rollback disables
further appends. No-learning STATE replies incur no outbox write. LOCAL LEARN
keeps its existing durable client-spool/ACK route. Legacy engines retain their
own synchronous durable writer and negotiation fallback; no new engine protocol
version or shim/ABI change is required by this host-side durability boundary.

The worker waits for the earliest reservation to be sealed, so later clients
can flush their own records without overtaking dictionary updates. Its full
checkpoint atomically includes =;; EG2 provider ID= alongside learned rows.
Replay skips ids already in that checkpoint. The worker also atomically saves
an independent =.eg2-provider-watermark= before completing its durability fence,
so a legacy engine's later dictionary rewrite cannot erase operation identity.
That worker-owned I/O does not hold the engine or outbox append mutex. Once
all appended records are checkpointed, the outbox is truncated and flushed.
Growing bursts are not repeatedly rewritten. Failed retirement may leave stale
records, which the durable watermark makes safe to skip. Watermark failure
retries the same FIFO job; shutdown failure retains the producer record for
startup replay. The pre-reply guarantee therefore does not depend on worker
success or orderly shutdown.

Startup recovers complete staged checkpoints, validates the provider outbox and
independent watermark, then replays unretired records in operation-id order
before loading the interpreter. Complete corrupt records/cursors fail startup
closed. An incomplete trailing record was not acknowledged and is discarded
only after all complete records are durable. Repeated replay after publication
but before retirement cannot reorder newer candidates or increment learning
revision again. Native tests model an old-engine save dropping unknown comments
and verify replay/monotonic ids still work. No personal dictionary or live
settings were used by these tests.
