#+TITLE: NeLisp IME: GNU Emacs integration

* GNU Emacs / evil on Windows
Add the repository's =emacs/= directory to =load-path=, then:
#+begin_src emacs-lisp
(require 'nelisp-ime-emacs)
(add-hook 'nelisp-ime-emacs-before-open-hook #'nelisp-ime-emacs-outside-org-src-p)
(nelisp-ime-emacs-mode 1)
#+end_src
The global mode follows evil, including evil loaded later: entering
insert/replace opens the TSF IME; entering other states closes it and restores
evil's cursor. Only state entries in the selected window's buffer change the
IME. Enabling the mode, focus changes, buffer/window switches, temporary
buffers and timer ticks never open or close it. Without evil, polling still
shows the IME mode but leaves opening and closing to the user. The optional
predicate above vetoes opening inside Org source blocks.
Customize =nelisp-ime-emacs-open-states=, =nelisp-ime-emacs-poll-interval=
(0.1 seconds), =nelisp-ime-emacs-dark-colors= / =nelisp-ime-emacs-light-colors=,
and =nelisp-ime-emacs-mode-line=. Registry polling only reads while a frame
has focus. Keep Emacs DDSKK disabled when using TSF.

Once, import these settings (the library cannot write the registry):
#+begin_src conf
Windows Registry Editor Version 5.00

[HKEY_CURRENT_USER\Software\NativeIME\Apps\emacs.exe]
"OpenMode"="latin"
"PublishState"=dword:00000001
"InlinePreedit"=dword:00000001
#+end_src
Optional DWORD =ModeIndicator= under =Apps\<exe>= controls the transient
caret popup: =0= disables it, =1= enables it, and an absent value uses the
global =ModeIndicator= setting. The taskbar icon and resident Sumi pill still
update. The popup uses the TSF caret, connected inline listener's last caret,
or focused window's system caret, in that order; without a caret it stays
hidden. It is mouse-transparent and never uses the mouse position.

Choose =hiragana= or =katakana= to open in kana. =restore= (default) preserves
the prior mode. Other applications retain existing behavior unless configured
under =Apps\<lowercase executable filename>=. The library warns once when
=PublishState= is off. A private installation must set the DLL environment
=NATIVEIME_REGISTRY_KEY= and =nelisp-ime-emacs-registry-key= to the same
HKCU-relative key.

With =PublishState=1 the DLL queues changed snapshots to =Clients\<pid>=:
=mode= (REG_SZ, the engine's own name), =open= (DWORD 0/1), =composing= (DWORD
0 none, 1 reading/pending romaji, 2 candidates), and =sequence= (DWORD,
incremented on each transition). Writes run through the message queue,
outside TSF key callbacks; unchanged snapshots are not rewritten.
An additional =revision= DWORD is odd during a multi-value write and even
when complete; the Emacs reader requires matching even revisions around
its snapshot.
Deactivation removes the entry. The host sweeps dead PIDs once per second,
including forcibly terminated applications.
Observed engine names in native/frontend and stateline sources are
=hiragana=, =katakana=, =latin=, =wide-latin=, =abbrev=, =preedit=, =candidate=,
=registration=. The frontend UI also uses =provider-preview= and
=provider-busy=. The cursor retains its prior script during composition.
Color alists additionally accept =jisx0201= for half-width katakana; current
engines produce that as a transliteration rather than a persistent input mode.

=nelisp-ime-emacs-inline-preedit= defaults to =t=.  While the global mode is
on, Emacs listens on an OS-chosen TCP port on =127.0.0.1= and publishes
=<pid>.json= with a version, port and a fresh 32-hex authentication token.
The discovery directory is =NELISP_IME_INLINE_DIR= when set, otherwise
=%LOCALAPPDATA%\DDSKK\emacs-inline= on Windows.  Set
=nelisp-ime-emacs-inline-directory= to override that default.  On other
systems, explicitly setting the environment variable or directory opts in.
Directory changes through Customize restart the listener; environment changes
take effect after toggling the global mode.  Disabling the inline option through
Customize or disabling the global mode closes all connections and removes the
discovery file.  Normal Emacs exit also removes it.

With a core implementing inline Protocol v1, =InlinePreedit=1 and an
authenticated connection suppress the system composition window.  Emacs
displays the full =▽かな= / =▼漢字= preedit at point, including in read-only
buffers and the minibuffer, using the underlined =nelisp-ime-emacs-preedit=
face.  This overlay leaves the buffer and undo history unchanged.  Committed
text continues to arrive through normal IME input.  With the option off or
no connected subscriber, the core uses normal system composition.

The Windows core reads =Apps\emacs.exe\InlinePreedit= as DWORD 1 under
the settings key (=NATIVEIME_REGISTRY_KEY= is honored).  It pins this choice
at preedit start; a dropped channel materializes the latest preedit through
ordinary composition without replaying keys.  Discovery retries once per
second on a worker thread, which also authenticates, sends coalesced updates,
and receives CARET.  In inline mode the core publishes that caret through
the existing Sumi caret bridge, so the regular candidate panel appears below
it with its usual styling and controls.  No extra core popup is created.
Commits use =ITfInsertAtSelection= with
=TF_IAS_NO_DEFAULT_COMPOSITION= in an edit session: no temporary TSF
composition is created.  Committed text arrives through normal IME input.
Protocol v1.1 listeners advertise =OK 1 pair=.  For an auto-paired kana-mode
commit, the core sends =PAIR <seq> <opener> <closer>= with both strings
percent-encoded like PREEDIT.  Pairs are configured only in =input-rules.conf=.
Emacs waits up to two seconds for the opener, or matches an opener inserted
at point within the preceding two seconds, then inserts the closer with point
between them.  Older requests and insertions are ignored.  Buffer modification
hooks, read-only fields, and minibuffer insertion restrictions still apply.

The private TSF harness checks insertion; IMM32 =GCS_RESULTSTR=/character
delivery and absence of a visible composition window still require a live
Windows Emacs check.

Private core integration tests (supply build/runtime paths as parameters):
=python windows/test-host/test-inline-preedit.py --dll DLL --core CORE
--tsf-host TSFHOST --engine-host ENGINEHOST --runtime NELISP --artifacts DIR
--case inline=.  Cases =missing=, =wrong=, =drop= and =emacs= cover fallback
and the real batch Emacs listener.  Batch CARET coordinates are stubbed;
overlay rendering and TCP transport use the real library.  The candidate
check uses a private Win32 observer of the caret bridge and counts it plus
any extra core popup; actual Sumi rendering and placement require a live check.

Protocol v1 uses UTF-8, LF-terminated lines.  The core sends
=HELLO 1 <token> <pid>=; Emacs replies =OK 1 pair= (legacy listeners reply
=OK 1=), or closes a bad connection.
An authenticated replacement closes the previous client.  The core sends
=PREEDIT <seq> <cursor> <text>= or =CLEAR <seq>=; only increasing sequence
numbers apply.  Cursor indices count Unicode code points, including the
endpoint.  Text escapes only percent, space, CR and LF as =%25=, =%20=,
=%0D= and =%0A=.  Emacs sends changed =CARET <x> <y> <height>= screen-pixel
coordinates after the handshake and on point, window, size, focus or preedit
changes.  Unavailable display coordinates are skipped in batch/terminal use.

#+begin_src sh

#+end_src

=-DllPath=, =-TsfHostExe=, =-EngineHostPath=, =-EngineExecutablePath= and
=-ColdLoadSleepSec 45=. It uses only disposable registry/pipe settings.

* Updating the Windows core without restarting applications
The registered =ddskk-ime.dll= is a stable TSF shim. Install it with its
adjacent =ddskk-ime-core.dll= and restart applications once. Later builds
can use =windows/scripts/deploy-live.ps1 -Core -BuildDirectory <Release-dir>=:
the script copies the core into an immutable versioned directory and sets
=CoreDll= under the settings key (including =NATIVEIME_REGISTRY_KEY= overrides).
Running clients swap on their TSF thread once composition, candidate UI,
provider requests and key dispatch are idle. Input mode, open/close state,
settings and the engine session survive. ABI/load/initialisation failures
keep the previous core and are logged to =DDSKK/dll-debug.log=.
Use =rollback-live.ps1 -Manifest <core-directory>/rollback.json= to restore
the previous pointer without restarting a process. Validated modules retain
reference-counted process-lifetime leases because TSF may retain callbacks;
repeated version updates therefore consume additional DLL address space.
Changes to the shim itself still require one application restart.

* Kana input rules
=nelisp-ime-keymap.exe --rules= opens the Japanese 入力規則 page; the keymap
editor also has an 入力規則 button. Choose 半角/全角 and automatic bracket
closing, then select a symbol/pair row to edit it, or add a row. Saving
preserves comments and writes atomically. External edits reload the page;
unsaved edits require an explicit reload before overwriting a changed file.
The file is UTF-8: =$NELISP_IME_INPUT_RULES= when set, otherwise inherited
=%APPDATA%\NativeIME\input-rules.conf=. The registry =InputRulesFile=
override is not supported for now. Missing files use the user's DDSKK
defaults (half-width punctuation, comma/period followed by a space, and
automatic bracket closing). See =windows/keymap/input-rules.conf= for the
complete commented template. For example:

#+begin_src conf
width = hankaku # hankaku | zenkaku
auto-pair = yes # yes | no
[symbols-hankaku]
. = ". "
"z " = " "
[pairs-hankaku]
[ = "「" "」"
#+end_src

Quoted strings preserve spaces; escape quotes/backslashes with a backslash.
Sections are =symbols-hankaku=, =symbols-zenkaku=, =pairs-hankaku=,
=pairs-zenkaku=, and =pairs= (openers emitted by other normal rules).
An invalid line is reported by number and skipped; remaining valid lines
override defaults. Width tables apply only in hiragana/katakana. Pair
metadata, effective width, auto-pair and errors share the existing rule
export. The resident keymap process watches this file outside its keyboard
hook, debounces edits for 200 ms and sends =ENGINE RELOAD=, retrying a busy
pipe. The editor can also request reload after saving. Engine replacement
and rule publication preserve running application processes.

The core inserts both bracket strings in its TSF commit edit session and
sets the caret before the closer. Backspace is then application-owned;
deleting an opener retains the closer, as in DDSKK. Special midashi are
excluded. Active-region wrapping is deliberately omitted. IMM32 depends
on CUAS exposing a TSF context; the isolated legacy EDIT probe on this
machine currently cannot obtain one (=E_NOINTERFACE=), so IMM32 caret
placement remains unverified. No injected-key fallback is implemented.
The TSF core changes require no shim or ABI change. For an operator-created
Start Menu entry, run =windows/keymap/New-RulesShortcut.ps1 -Executable
<nelisp-ime-keymap.exe>=; it points to =--rules=. The script is not run by
the input-rules tests.

The focused ERT suite is =engine/test-input-rules.el=. Build the separate
extended TSF/IMM32 fixtures with =cmake -S windows/test-host/input-rules
-B build/input-rules -G "Visual Studio 17 2022" -A x64= and invoke
=test-input-rules.ps1= in that directory with explicit build directories,
keymap executable and engine executable. Tests use private settings,
pipes and local AppData, and never send synthetic keyboard input.
