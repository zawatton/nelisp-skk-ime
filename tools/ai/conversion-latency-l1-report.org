* Reproduction and measurement
The first unchanged-engine exploratory run tried KieRu, a behavior-fixture
reading absent from L. It correctly returned registration:
#+begin_example
Conversion failed kieru: STATE registration 0 -1 - - -1 - 00304d003048000072
#+end_example
The corrected key corpus was checked against L: Kana, Kanji, Nihon, Ka,
KaKu, YoMu. No entries from a personal dictionary were used. Timed warm samples
cancel rather than commit, so learning cannot turn shared-dictionary
conversion into a one-candidate personal-dictionary hit. Each kind starts
a fresh host/engine; the first request after a 45-second load wait is cold.

Each request is SESSION bench CONTROL CONVERT-KEYS with decimal codepoints.
CPU is the child process TotalProcessorTime delta. p50/p90 use nearest rank;
CPU granularity on this Windows machine is approximately 15.625 ms.
Wall time covers the whole host request and excludes corpus encoding.
Each run owns its pipe, registry-key name, LOCALAPPDATA, user jisyo and
dictionary copy. Hosts own kill-on-close jobs for runtime children.

Load snapshots are embedded in every JSON. This is a 20-logical-processor
machine. The first baseline's approximate one-second opening snapshot
had emacs and python each using 1359.4 ms CPU; closing snapshot had several
other NeLisp/Emacs processes using roughly 1640-1688 ms each. Server-enabled
baseline closed with cl at 1281.2 ms. These are loaded-machine results,
not quiet wall-clock acceptance evidence. Later snapshots record the actual
snapshot interval and quiet retries. Quiet selection rejects another
process above 0.3 CPU seconds per elapsed second, retries at five-second
intervals, and retains every observed load. It never stops other workers.

Opt-in wrappers send PHASE enter/leave markers consumed by the existing
host. The summarizer reconstructs inclusive and self time with a stack.
These are instrumented wall times, rounded to the host's approximately
16-ms timestamp granularity, not exact per-function CPU measurements.

After optimization, the same plain trace has 21 snapshots rather than 41;
hex self time 328 ms rather than 437; outer dispatch inclusive 1047 ms
rather than 1234. This is evidence of eliminated work, not proof of S2.1.
The trace includes dispatch/protocol parsing in outer self time; it does
not isolate protocol parsing from all other glue. No explicit collection
was observed inside the instrumented conversions. The runtime probe
(list (fboundp 'gc-stats) (fboundp 'garbage-collect)
      (fboundp 'nelisp-artifact-load-file)) returned (nil t nil).
Automatic runtime GC is not separately observable by this instrumentation.
Therefore S1.2's full GC/parse separation remains incomplete.

The read-only runtime sample-profile.sh documents gdb attach sampling;
runtime Doc 201 explains each attachment may cost 0.3-3 seconds. That is
unsuitable for a single subsecond request here. The traces identify
interpreted command dispatch and scalar encoding as hot paths. Proposed
runtime work: expose allocation/GC CPU counters to the engine; provide the
same native artifact loader in ordinary source/stdio execution as in the
artifact CLI; then sample evaluator dispatch/root-frame construction
over many repeated requests. No runtime attribution is claimed without
sampling evidence.

* Native compilation investigation
engine/ddskk-hotpath.neln contains only ascii-vowel-p and decimal-step.
No engine/ or host source loads or calls those probes. Conversion functions
therefore still execute from source in the current host path.

The read-only hosted compiler accepts three extracted production loops:
#+begin_example
((:name "ddskk-engine--hex-uncached" :native t)
 (:name "ddskk-engine--decode-codepoints" :native t)
 (:name "ddskk-engine--parse-server-reply" :native t))
#+end_example
The runtime artifact CLI evaluates the decode probe to "Ka". Ordinary
engine-path load of the artifact fails with void-function (:format).
Calling nelisp-artifact-load-file fails with void-function. Loading the
read-only artifact implementation first gets further, but fails with
nelisp-artifact-invalid: ("unsupported manifest format" nil ...).
The executable reports these errors while exiting zero; exit status alone
cannot validate such a probe. No native artifact was installed or claimed
to execute in the production engine.

pass the comparator (80 plain/40 okuri; ratio 0.500; PASS S2.1: 2/2 kinds).
